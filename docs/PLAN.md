# 项目方案

## 一句话定位

给不懂 AI 的个人用户准备的**翻唱全流程工具**：装好、喂素材、跑一条命令，出成品。
把「训练 → 分离 → 转换 → 混音 → 挑段」这条原本要手动折腾半天的链路固化成可复现的流程。

## 目标用户

- 想给自己做个翻唱音色，但被 RVC WebUI 的参数和环境劝退的人
- 只想「输入歌名，输出成品」，不关心 f0 算法和 index_rate 的人
- 有 8G 显卡、Windows 电脑的普通用户

不面向：要极致音质调参的进阶玩家（他们会直接用 RVC）、要批量生产的商业场景。

## 和现有项目的差别

| | 现有 RVC 生态 | 本项目 |
|---|---|---|
| 形态 | WebUI 点按钮 | 命令行一条龙 + 可选网页界面 |
| 训练 | 手动准备数据集、自己切 | 素材丢进去，自动清洗切分并评估够不够 |
| 分离 | 另开 UVR 界面 | 流程内置 |
| 挑段 | 自己听、自己截 | 按能量自动找副歌 |
| 缓存 | 没有 | 成品比模型新就秒复用，模型重训自动重跑 |
| 报错 | 堆栈 | 人话 + 下一步该干什么 |

## 项目内容（模块）

| 模块 | 职责 | 现状 |
|---|---|---|
| `cli` | 命令入口：init / doctor / train / sing / sources / gui | 完成 |
| `config` | 默认值 → 预设 → 本地覆盖 → 命令行覆盖 | 完成 |
| `sources` | 音源适配层 + 插件注册 | 完成（内置 local_file） |
| `core/separate` | 人声分离（UVR 后端） | 接口完成，依赖待装 |
| `core/convert` | 音色转换（RVC 库或外部命令模板） | 接口完成，依赖待装 |
| `core/pitch` | 自动降调（中位基频判断） | 完成（可选 librosa） |
| `core/mix` | 混音 + 响度归一 | 完成 |
| `core/clip` | 能量峰值挑段、全曲切段 | 完成 |
| `pipelines/train` | 素材扫描 → 清洗切分 → 数据集 → 训练 | 完成前半段 |
| `pipelines/sing` | 源文件 → 分离 → 转换 → 混音 → 挑段，带缓存 | 完成 |
| `webui` | 拖文件点按钮的本地界面（gradio） | 骨架 |

## 呈现形式

1. **命令行为主**：`cover` 一个入口，子命令清晰，中文提示
2. **可选网页界面**：`cover gui` 起本地页面，拖文件、点按钮，适合完全不想碰终端的人
3. **文档分层**：README 一页看懂；QUICKSTART 手把手；TRAIN 讲素材和参数；SOURCES 讲插件；DISCLAIMER 讲边界
4. **发布形态**：GitHub 仓库 + MIT 许可 + 中文为主英文 README 并行；不发布模型、不发布音源工具

## 边界（不做的事）

- 不内置任何音源获取/解密工具，只在 `plugins/` 留接口，由用户自己实现
- 不提供预训练音色模型，训练素材必须用户自己提供且有授权
- 不在文档里教怎么绕过版权保护
- 不追求覆盖所有显卡/系统，第一版只保 Windows + NVIDIA

## 里程碑

| 阶段 | 内容 | 预估 |
|---|---|---|
| M1 | 骨架 + 命令 + 配置 + 文档（当前） | 完成 |
| M2 | 接上 UVR 与 RVC，跑通一首真实翻唱 | 1~2 天 |
| M3 | 训练链路打通（外部命令模板 + 文档） | 1 天 |
| M4 | 网页界面可用 | 1 天 |
| M5 | 英文 README、示例音频、常见问题补全 | 1 天 |
| M6 | 发布到 GitHub，收第一轮反馈 | — |

## 风险

- **环境装不上**是最大的劝退点，需要一键脚本 + 明确报错，M2 之后要专门测
- **质量不稳定**（素材差、模型差）会带来差评，文档里要把预期讲清楚
- **版权与合规**：边界必须写死，README 和文档都要有明确声明
- **维护成本**：RVC 生态变动快，接口要用「外部命令模板」这种松耦合方式，别硬绑某个库版本
