# 项目复核（2026-11-05，v0.2.2）

## 一、定位复核

**原始定位**：给 AI 新手的翻唱流水线——模型训练（用户提供素材）、人声分离、翻唱，整套流程一条命令跑完；能复用本机已装环境；能被别的 Agent 调用。

**现状**：定位没跑偏，但重心从「一条命令」变成了「三层编排」：

| 层 | 内容 | 状态 |
|---|---|---|
| 能力层 | 分离 / 转换 / 混音 / 挑段 / 训练 | 跑通，真歌实测 3 分钟出片 |
| 决策层 | 硬件探测 → 方案推荐 → 症状配方 → 模型版本 | 完成，11 套方案 / 6 类症状 / 版本可回滚 |
| 交付层 | CLI + 网页界面 + Agent API + 打包 | 前三个完成，**打包缺** |

一句话定位建议固定为：**「把 RVC 翻唱这套零散工具，编排成小白能跑通、Agent 能调用的一条流水线」**。

**目标用户**（按优先级）：
1. 装过 RVC/UVR、被环境和参数劝退的人 —— 主路径，`cover link` 直接复用
2. 有显卡想给自己声音做翻唱的新手 —— 走方案 + 向导
3. 想把自己工具链接进来的开发者 —— 走 CLI / API / 插件

**明确不做**：不做解密、不分享音色模型、不做在线托管、不做模型市场。

## 二、需求覆盖核对

| 需求（出自使用者） | 状态 | 落在哪 |
|---|---|---|
| 一条命令跑完训练/分离/翻唱 | ✅ | `cover train` / `cover sing` |
| 复用本机已装 RVC/UVR，不重装 | ✅ | `cover link`、`separate.backend=local_uvr` |
| 硬件不同给不同参数，讲清利弊 | ✅ | `cover plan`、`plans/*.yaml` |

| GitHub 发布 | ⏸ 暂缓 | 维护者决定先自测 |

## 三、本次复核发现并修掉的问题

配置里写了但代码没读的「僵尸配置」，全部接上了：

| 配置项 | 原来的问题 | 现在 |
|---|---|---|
| `clip.mode` | 只在注释里，挑段永远按副歌 | 支持 chorus / start / middle / full |
| `clip.energy_window` | 硬编码 0.5 秒 | 按配置走 |
| `separate.keep_backing` | 永远保留伴奏 | false 时丢弃伴奏 |
| `device.gpu_index` | 多卡机器没得选 | 写进 `CUDA_VISIBLE_DEVICES` |
| `train.clean` | 注释说会清洗，实际没实现 | 按 mean_volume 过滤过安静片段（阈值 `clean_threshold_db`，默认 -40dB） |
| `send.enabled` / `target` / `account` | 发布插件写好了但没人调 | 成品生成后按需调用发布插件，target/account 传给插件 |
| `project.log_level` | 只在 `--verbose` 时变 | 读取配置，命令行与配置文件都生效 |

## 五、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 上游接口变动 | 网易云/QQ 音乐/B站的公开接口随时可能改或加签 | 已把每个平台隔离成独立函数，坏了只影响一家；搜索页可勾选来源 |
| 依赖体积 | torch 4~6G，新手容易卡在安装 | 主路径是复用本机环境；pip 档位作为备选 |
| 版权边界 | 下载与解密是敏感区 | 不内置解密、不分享模型、文档写清；高音质只留接口 |
| 单机假设 | 现在是单用户本地服务，没有鉴权 | 只监听 127.0.0.1；对外暴露需要先加鉴权 |
